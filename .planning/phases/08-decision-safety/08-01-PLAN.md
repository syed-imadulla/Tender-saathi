## 1. Architectural Guardrails & Invariants

1. **Anti-Fallthrough Invariant**:
   *A secondary candidate may never be promoted merely because it survived a weaker check.*
2. **Decision-Sensitive Completeness**:
   A missing parameter triggers review or abstention *only* when that parameter is necessary to distinguish viable candidates or resolve an operational conflict.
3. **Evidence Grounding Invariant**:
   $\text{candidate\_standard} == \text{evidence\_standard}$ on 100% of emitted recommendations.
4. **Zero Hardcoding**:
   Zero `ADV-*` probe IDs, probe strings, or synthetic exceptions in production code.
5. **Zero Fabricated Thresholds**:
   Operating condition bounds derive strictly from verified standard scopes; omitted constraints evaluate to `UNKNOWN` / `REVIEW_REQUIRED`.
6. **Asset Immutability**:
   `dataset/ground_truth/`, `data/catalogue/`, and `dataset/adversarial/` remain 100% untouched.

### Task 1: Semantic Role Separation in Technical Token Extraction
- **Files Involved**: `src/applicability.py` (`extract_technical_tokens`, `evaluate_candidate`)
- **Hypothesis**: Non-engineering corporate governance/administrative actions (`audit`, `compliance`, `hiring`, `statutory`, `taxation`, `firm`) currently masquerade as "technical tokens", causing false token overlap with food hygiene codes. Constraining technical token extraction to physical entities, engineering materials, equipment, and industrial processes will allow non-engineering commodity tenders to evaluate to `NO_RELIABLE_MATCH` without relying on keyword blacklists.
- **Implementation Specification**:
  1. In `src/applicability.py`:
     - Refine `extract_technical_tokens`: Categorize tokens into semantic roles. Administrative, contractual, corporate governance, and general procurement actions are recognized as *administrative modifiers* rather than *physical technical entities*.
     - Ensure `product_match` and `substantive_overlap` require at least one verified physical product/material/equipment entity.
     - When a tender contains zero physical engineering entities, evaluate applicability as `ApplicabilityReasonCode.OUT_OF_DOMAIN` / `NO_RELIABLE_MATCH`.
- **Target Probes**: `ADV-ABS-002`, `ADV-INJ-003`.
- **Regression Tests**:
  - `test_statutory_financial_audit_has_zero_technical_product_tokens()`
  - `test_corporate_accounting_firm_evaluates_to_no_reliable_match()`
  - `test_genuine_quality_audit_preserves_product_tokens()` (e.g. food hygiene audit with food equipment)
- **Target Metric**: False-Positive Rejection Rate reaches **5/5 (100.0%)**.

### Task 2: Ingestion Trust Boundary & Sanitized Query Stream
- **Files Involved**: `src/extract.py`, `src/retrieval.py`
- **Hypothesis**: Injected JSON payloads (e.g. `{"candidate_standard": "IS 1786"}`) and override commands currently pass directly into `HybridRetrievalEngine` and `extract_technical_tokens` because sanitization is only performed during citation extraction. Neutralizing structured injection syntax from the working query stream before hybrid retrieval and token extraction will eliminate prompt pollution.
- **Implementation Specification**:
  1. In `src/extract.py`:
     - Preserve raw tender text untouched in `Requirement.raw_context` for audit trails and human review.
     - Provide a sanitized working representation `sanitized_query_text` that neutralizes structural JSON objects (`\{[^{}]*"[a-zA-Z_]+"\s*:[^{}]*\}`), directive commands (`SYSTEM OVERRIDE:`, `INSTRUCTION:`, `Return JSON:`), and adversarial injection prefixes.
  2. In `src/retrieval.py` (`HybridRetrievalEngine.search`):
     - Execute BM25 and semantic vector search on the sanitized working query text rather than the raw un-sanitized string.
     - Prevents fake standard numbers (`IS 9999`) or payload standard numbers (`IS 1786`) from creating spurious vector or token matches on unrelated tenders.
- **Target Probes**: `ADV-INJ-001`, `ADV-INJ-004`.
- **Regression Tests**:
  - `test_json_payload_injection_neutralized_in_retrieval()`
  - `test_system_override_tokens_do_not_distort_query_embedding()`
  - `test_raw_context_preserved_intact()`
- **Target Metric**: Prompt-Injection Containment Rate reaches **5/5 (100.0%)**.

### Task 3: Pre-Citation Operational Envelope Validation
- **Files Involved**: `src/recommend.py`, `src/ambiguity.py`
- **Hypothesis**: Explicit tender citations currently receive an automatic 1.0 confidence score bonus before verifying whether the cited standard's physical scope contradicts the requirement's operational environment. Gating the citation bonus on operational compatibility will prevent unsafe recommendations on contradictory tenders.
- **Implementation Specification**:
  1. In `src/recommend.py` (Citation Handling Phase):
     - Before granting the 1.0 confidence score bonus to an explicitly cited standard, execute `ApplicabilityGate.evaluate_candidate` and `ConflictRegistry.check_conflict`.
     - If the cited standard's physical scope conflicts with the tender's stated operating condition (e.g. concrete drainage pipe cited for high-pressure steam, or wall tile cited for blast furnace flooring):
       - Strip the 1.0 score bonus.
       - Set `applicability = ApplicabilityDecision.INCOMPATIBLE`.
       - Set `ambiguity_state = AmbiguityState.CONFLICTING`.
       - Set `candidate_standard = None` and `human_review_required = True`.
- **Target Probes**: `ADV-APP-002`, `ADV-APP-005`.
- **Regression Tests**:
  - `test_concrete_pipe_steam_citation_bonus_stripped()`
  - `test_wall_tile_blast_furnace_floor_citation_conflict_abstains()`
  - `test_valid_explicit_citation_preserves_score_bonus()`
- **Target Metric**: Unsafe Confident Recommendation Rate drops to **$\le 1/61$ ($\le 1.6\%$)**.

### Task 4: Independent Candidate Viability Invariant (Anti-Fallthrough)
- **Files Involved**: `src/recommend.py`, `src/applicability.py`
- **Hypothesis**: When the primary candidate matching a tender is disqualified for operational mismatch (e.g. CPVC rejected for steam, wire rejected for furnace, pump rejected for acid, or cited standard nonexistent), the recommender currently defaults to secondary candidates that survived merely because they lacked an explicit rule. Evaluating candidates independently against the operating environment and abstaining when the viable pool is exhausted will eliminate fallthrough recommendations.
- **Implementation Specification**:
  1. In `src/recommend.py` (Candidate Pool Viability):
     - Evaluate EACH retrieved candidate independently against domain and operational compatibility.
     - Secondary candidates do not inherit viability by omission: a drainage pipe (`IS 14333`) or structural rebar (`IS 1786`) must independently satisfy the requirement's operational medium (e.g. steam service, furnace temperature, corrosive acid).
     - Form the `viable_candidates` list containing only candidates that independently satisfy physical applicability.
     - If `viable_candidates` is empty:
       - Enforce clean abstention: `candidate_standard = None`, `ambiguity_state = NO_RELIABLE_MATCH` / `INCOMPATIBLE`.
       - Mandate human review with explicit disqualification audit trail in `why_not`.
       - Never promote a secondary candidate from an exhausted or incompatible pool.
  2. For invalid/nonexistent explicit citations (`ADV-BND-004`):
     - If a tender explicitly demands compliance with a specific cited standard that is uncatalogued/nonexistent, the system must NOT fall back to arbitrary alternative standards on residual text. It must cleanly abstain with `candidate_standard = None` and request engineer verification.
- **Target Probes**: `ADV-APP-001`, `ADV-APP-003`, `ADV-APP-004`, `ADV-BND-004`, `ADV-CON-002`.
- **Regression Tests**:
  - `test_cpvc_steam_secondary_candidate_not_promoted()`
  - `test_furnace_wire_exhausted_pool_abstains_cleanly()`
  - `test_acid_pump_exhausted_pool_abstains_cleanly()`
  - `test_nonexistent_citation_forces_clean_abstention()`
- **Target Metric**: Safe-Abstention Rate reaches **$\ge 14/15$ ($\ge 93.3\%$)**.

### Task 5: Unified Decision Safety Gate
- **Files Involved**: `src/recommend.py`
- **Hypothesis**: Human review routing is currently fragmented across multiple decoupled modules, allowing high retrieval scores or default critic decisions to suppress human review on severe domain conflicts and competing grades. A consolidated terminal safety gate will ensure zero high-risk recommendations escape unflagged.
- **Implementation Specification**:
  1. In `src/recommend.py` (Terminal Decision Consolidation):
     - Replace fragmented `if/elif` review logic with a single unified gate evaluated immediately before returning `RequirementRecommendationResult`.
     - Mandate `human_review_required = True` whenever ANY of the following hold:
       - `candidate_standard is None` (all abstentions and unresolvable tenders require engineer review).
       - Any operational conflict or duty mismatch detected in `ConflictRegistry`.
       - Competing structural grades present (e.g. mild steel `IS 432` vs TMT `IS 1786` for concrete columns).
       - Explicit tender citation is unrecognized, unverified, or contradicts the requirement.
       - Distinguishing parameters required to differentiate viable candidates are omitted.
       - Standard lifecycle role is `OLDER_VERSION`, `SUPERSEDED`, or `WITHDRAWN`.
     - Remove uncalibrated magic retrieval score thresholds (no arbitrary `< 0.50` rule).
- **Target Probes**: `ADV-DUP-003`, `ADV-CON-004`, `ADV-CON-002`, `ADV-LEX-005`.
- **Regression Tests**:
  - `test_mild_steel_column_flags_mandatory_human_review()`
  - `test_tmt_citing_mild_steel_flags_mandatory_human_review()`
  - `test_unresolved_conflict_mandates_human_review()`
- **Target Metric**: Human-Review Routing Recall reaches **$\ge 44/46$ ($\ge 95.7\%$)**.

### Task 6: Retrieval & Composite Requirement Resolution (M6)
- **Files Involved**: `src/decompose.py`, `src/retrieval.py`, `src/search.py`
- **Hypothesis**: The remaining algorithmic retrieval failures (`ADV-LEX-004`, `ADV-RET-001`, `ADV-RET-004`, `ADV-MUL-004`) stem from compound modifier ambiguity, technical paraphrasing mismatch, and multi-component role assignment. Generalized linguistic and representation enhancements will resolve these failures without probe-specific logic.
- **Core Invariant**: Zero direct phrase-to-standard-number mapping in production code. The system must NOT directly select a standard number from a requirement phrase. Candidate standards must strictly be obtained through catalogue retrieval based on enriched domain representation and generic functional roles.
- **Implementation Specification**:
  1. **Compound Head-Noun Binding (`src/decompose.py`, `src/retrieval.py`)**:
     - For multi-modifier phrases ("agricultural motor oil immersion heater elements"), ensure compound parsing binds "heater element" as the primary functional head noun, down-weighting standards that match only context modifiers ("oil-immersed transformer", "induction motor").
  2. **Domain-Aware Technical Paraphrase Representation (`src/retrieval.py`, `src/search.py`)**:
     - Normalize dense chemical, metallurgical, and physical descriptions to standardized domain concepts/materials *within the query stream* (improving the representation used for retrieval rather than bypassing retrieval):
       - Chemical formulation: "post-chlorinated vinyl synthetic polymer" $\rightarrow$ normalized query concepts: "chlorinated polyvinyl chloride", "cpvc pipe".
       - Metallurgical process: "thermo-mechanically processed ferrous cylindrical rods with surface ribs" $\rightarrow$ normalized query concepts: "tmt steel bars", "high strength deformed steel bars", "concrete reinforcement".
     - The normalized concepts enrich the *working query representation* fed into the hybrid retrieval engine (`BM25` + dense semantic search) across the 35,208-record catalogue. Candidate standards are obtained strictly through catalogue retrieval.
  3. **Composite Requirement Generic Component Role Assignment (`src/decompose.py`, `src/recommend.py`)**:
     - In composite multi-component industrial requirements (e.g. electrical substations comprising transformers, distribution pillars, and earthing), classify sub-components into generic functional archetypes:
       - `ENERGY_TRANSFORMATION_COMPONENT` (e.g. transformer, generator, boiler)
       - `DISTRIBUTION_COMPONENT` (e.g. distribution pillar, switchboard, busbar)
       - `PROTECTIVE_COMPONENT` (e.g. circuit breaker, fuse, surge arrester)
       - `EARTHING_AND_SAFETY_COMPONENT` (e.g. earthing station, ground conductor)
     - Rank the core energy-transformation component over secondary distribution or auxiliary components. The candidate standard is obtained strictly from the retrieved candidates for that component role, never hardcoded from a requirement phrase.
- **Target Probes (Empirical Behavioral Assertions)**: `ADV-LEX-004`, `ADV-RET-001`, `ADV-RET-004`, `ADV-MUL-004`.
- **Regression Tests (Asserting Behavioral Outcomes, Not Implementation Mappings)**:
  - `test_oil_immersion_heater_retrieval_matches_appliance_or_abstains()`: Asserts that candidate standard is in `['IS 302', 'IS 302 (Part 1)', None]`, rejecting transformer and motor standards.
  - `test_post_chlorinated_polymer_paraphrase_retrieves_cpvc()`: Positive retrieval test asserting that candidate standard is NOT `None` and resolves to the CPVC catalogue standard (`IS 15778`), obtained strictly via catalogue retrieval.
  - `test_tmt_surface_ribs_paraphrase_retrieves_tmt_bars()`: Positive retrieval test asserting that candidate standard is NOT `None` and resolves to the TMT catalogue standard (`IS 1786`), obtained strictly via catalogue retrieval.
  - `test_substation_composite_selects_transformer_component()`: Asserts generic architectural behavior: decomposed sub-component has `primary_role == "ENERGY_TRANSFORMATION_COMPONENT"`, and selected candidate standard comes strictly from retrieved candidates for that role.
- **Target Metric**: Overall Adversarial Pass Rate reaches **$\ge 66/70$ ($\ge 94.3\%$)**.

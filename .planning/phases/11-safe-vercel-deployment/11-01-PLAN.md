## Implementation Plan (PLAN.md)

### Why Decoupled Deployment is Mandatory (Technical Findings)

1. **4.5 MB Serverless Payload Limit**: Real CPWD/MES/Railway tender PDFs often range between 5 MB and 35 MB. Vercel serverless functions strictly reject payloads $> 4.5$ MB with HTTP 413. A dedicated backend eliminates this bottleneck.
2. **Stateful Human Review Workflow**: `api/server.py` uses `_report_cache[tender_id]` across the 3-step pipeline (`/api/analyze/*` -> `/api/tender/<id>/review` -> `/api/report/<id>/*`). Serverless ephemeral containers route consecutive requests to different cold instances, resulting in cache-miss errors.
3. **ML Stack & System Binaries**: The ML runtime (`torch`, `sentence-transformers`, `scipy`, `pandas`) exceeds 1 GB uncompressed, and OCR requires system C libraries (`tesseract-ocr`, `poppler-utils`). These cannot run reliably in standard serverless runtimes.
4. **Invariant Preservation**: Invariant 7 states: *"Do not remove functionality simply because Vercel has runtime limitations."* Decoupling preserves 100% of verified capabilities without compromising product intelligence.

### Non-Negotiable Invariants

1. Do not switch away from `main`.
2. Do not rewrite Git history, force-push, or amend existing commits.
3. Do not modify:
   - BIS catalogue (`data/catalogue/bis_catalogue.db`)
   - Core standards (`data/standards/standards.db`)
   - Frozen ground truth (`dataset/ground_truth/ground_truth.csv`)
   - Adversarial evaluation dataset (`dataset/adversarial/adversarial_evaluation_suite.json`)
   - Recommendation, applicability, ambiguity, evidence, audit, review, relationship, or regulatory logic in `src/`.
4. Do not hardcode deployment-specific standards or mock recommendations.
5. Do not replace real data with mock data.
6. Do not remove PDF support or OCR support.
7. Do not commit secrets, API keys, tokens, or `.env` files.
8. Do not deploy production until preview deployment passes all verification gates.
9. If results change unexpectedly on regression tests (`pytest`, `src.evaluate`, `src.eval_adversarial`), STOP immediately.

### Workstream Breakdown

#### Task 11-01: Deployment Architecture & Repository Configuration
- **Objective**: Configure Vercel build and routing without disturbing local dev workflows.
- **Affected Files**:
  - `vercel.json` (New at root)
  - `frontend/src/api.ts` (Minimal update: allow `import.meta.env.VITE_API_URL || '/api'`)
- **Implementation**:
  - Create `vercel.json` specifying:
    - `"buildCommand": "cd frontend && npm install && npm run build"`
    - `"outputDirectory": "frontend/dist"`
    - `"framework": "vite"`
    - `"rewrites": [{"source": "/api/:path*", "destination": "https://<BACKEND_URL>/api/:path*"}, {"source": "/((?!api(?:/|$)).*)", "destination": "/index.html"}]`
  - In `frontend/src/api.ts`: set `const BASE = import.meta.env.VITE_API_URL || '/api';`. This guarantees:
    - In local dev: defaults to `/api` (proxied by Vite to `localhost:5000`).
    - In standard Vercel deploy: defaults to `/api` (proxied by Vercel rewrite).
    - If direct backend communication is desired for ultra-large PDF uploads, `VITE_API_URL` can point directly to backend.
- **Verification Criteria**:
  - `cd frontend && npm run build` succeeds cleanly in < 2 seconds.
  - Local dev `npm run dev` continues to proxy to `localhost:5000`.

#### Task 11-02: Backend Production Packaging
- **Objective**: Package the Python backend as a clean, reproducible container capable of running on any PaaS (Render, Railway, Fly.io, or VPS) with all required system binaries and SQLite assets.
- **Affected Files**:
  - `Dockerfile` (New at root)
  - `.dockerignore` (New at root)
  - `api/server.py` (Minimal runtime adaptation: configurable CORS and report directory)
- **Implementation**:
  - `Dockerfile`:
    - Base: `python:3.11-slim` or `python:3.12-slim`
    - System packages: `apt-get install -y --no-install-recommends tesseract-ocr poppler-utils gcc g++`
    - Python dependencies: install from `requirements.txt`
    - Copy data assets: `data/catalogue/bis_catalogue.db`, `data/standards/standards.db`
    - Ensure `reports/generated` is created and writable
    - Expose `PORT` (default 5000)
    - Run command: `python3 -m api.server` (or Gunicorn if included in container)
  - `api/server.py`:
    - Configure CORS to accept `CORS_ORIGINS` environment variable (e.g. comma-separated list of origins, matching `*.vercel.app` or `*` if configured), while keeping localhost origins as default.
    - Set `REPORT_DIR = os.environ.get("REPORT_DIR", os.path.join(ROOT_DIR, "reports", "generated"))`.
- **Verification Criteria**:
  - Docker container builds and starts cleanly.
  - `curl http://localhost:5000/api/health` returns `{"status":"ok","service":"TenderSaathi API"}`.
  - Zero modifications to recommendation algorithms or core logic.

- **Implementation**:

### Rollback Strategy

1. **Vercel Rollback**: Instant 1-click rollback via Vercel Dashboard or `vercel rollback <deployment-id>`. Prior deployment remains immutable.
2. **Git Rollback**: Since all deployment changes are isolated to `vercel.json`, `Dockerfile`, `.dockerignore`, and deployment docs, any failure can be reverted cleanly with `git revert` without impacting the verified Phase 10 baseline.
3. **Backend Service Rollback**: Prior container image tags are preserved on container registries or PaaS history.
